The standalone `infra/oracle/compose.yaml` targets ARM64 and runs API, Celery push worker, Beat, frontend, private password-protected Redis and HTTPS Caddy. An optional Alloy profile exports only aggregate platform metrics. It does not self-host TimescaleDB, Prometheus, Grafana, demo workloads or customer agents. The worker preserves Celery on Python 3.13 and frozen scoring on Python 3.14; `queue/Dockerfile.arm64` uses the separately locked official ARM CPU PyTorch wheel. Its multi-architecture base manifests and lock resolve, but the actual ARM image and frozen scoring tests have **not passed yet**. CI now requires native `ubuntu-24.04-arm` builds, image scans and the frozen inference/training suite before ARM images may publish. Do not start a live A1 rollout until these gates pass.

The 2026-09-28 offline Compose check passed with fixture settings: nine defined services, ARM64 platform throughout, only the edge exposing ports, and 4.62 GiB of configured service memory limits. GitHub Actions YAML parses and both publication jobs depend on the native ARM gates. Three push-contract tests and source lint passed; all 78 frozen artifact/lock/evidence hashes still match. These checks do not validate ARM wheels at runtime, OCI provisioning, DNS, TLS, Tiger Cloud connectivity, or Grafana Cloud remote writes.

`DATABASE_URL` accepts PostgreSQL connection strings and normalizes the SQLAlchemy driver without exposing credentials. Production requires SSL; prefer `sslmode=verify-full` with the Tiger Cloud certificate chain. The `migrate` profile runs a single advisory-locked Alembic predeploy, verifies Timescale extension and raw-metrics/feature-window hypertables, configures retention and encrypts legacy integration destinations. It requires a verified backup acknowledgement in production and refuses concurrent migrations. New app readiness requires revision `0008_push_pipeline`. Destructive downgrade is rejected; rollback uses a verified backup and the matching previous image.

Caddy provides same-origin `/api`, blocks public metrics/docs/chaos, and adds HSTS. Only its fixed private address is trusted for forwarded headers. Production cookies are Secure, host scoped and use explicit SameSite policies. Liveness is process-only; production readiness checks the database and does not depend on optional Slack, LLM or Grafana availability.

`infra/oracle/config.alloy` scrapes only the API's platform registry and aggregate Redis counters. Its metric/label allowlist excludes account IDs, customer host IDs, raw telemetry and customer collector scrapes. `platform-dashboard.json` supplies 19 panels covering API latency/errors, ingestion, rate-limit reasons, queue depth/tasks, predictions/duration/high risk, alerts, LLM, database failures, Redis and worker last success. Import it into Grafana Cloud with the Cloud metrics datasource, then verify actual remote writes before declaring observability live.

GitHub Actions installs the separately hash-locked SaaS runtime, validates frozen ML/leakage contracts, tenant cohorts, agent bundle, frontend, chart and images. A separate Linux job runs the actual disposable 100-host Redis/Celery/Beat cohort. Native ARM jobs build and scan API, frontend and push images and run the frozen inference/training suite. Publishing requires all test/build/scan jobs; ARM images get separate immutable digest references. No deploy secret or SSH private key is committed. Application rollout is an operator step using those digest references from a successful CI publication.
